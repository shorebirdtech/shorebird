# Contributing

We are happy to accept contributions!

## Developing

### FFI

The Dart code in this library communicates with the Updater (part of Shorebird's
Flutter engine) via FFI.

The Updater's Rust code lives in shorebirdtech/flutter at
[`engine/src/flutter/third_party/updater`](https://github.com/shorebirdtech/flutter/tree/shorebird/dev/engine/src/flutter/third_party/updater).
Its history before the move is in the archived
[shorebirdtech/updater](https://github.com/shorebirdtech/updater) repository.

For an Updater function to be visible to the Dart code, it must:

1. Be declared in the Updater's `library/src/c_api/dart.rs` as
   `pub extern "C"` (the Dart-stable surface). Functions only meant for the
   Flutter engine go in `library/src/c_api/engine.rs` instead and will not
   appear in the Dart bindings.
   1. The two buckets emit `library/include/updater_dart.h` and
      `library/include/updater_engine.h` respectively, generated by
      [cbindgen](https://github.com/mozilla/cbindgen) when the Updater is
      built.
1. Land in the Updater first, then be copied into this package: copy the
   Updater's `library/include/updater_dart.h` over
   [`native/updater_dart.h`](native/updater_dart.h) in the same change that
   uses the new symbol. That header is this package's ABI: an existing symbol
   never changes behavior, so the package detects each feature by its own
   symbols.
1. Be included in the generated ffi bindings. These can be regenerated using
   `dart run ffigen`. ffigen reads only `native/updater_dart.h`, so
   engine-only symbols are not bound.
1. Android specific: be listed in
   https://github.com/shorebirdtech/flutter/blob/shorebird/dev/engine/src/flutter/shell/platform/android/android_exports.lst

### Integration tests

The tests that drive this package's API against the real Rust Updater (through
its `library_test_hooks` cdylib and a fake patch server) live with the Rust
code, in the Updater's `integration_test/` package, and run on every Updater
change. This package's own tests (`test/`) are unit tests and need no Rust
toolchain.
